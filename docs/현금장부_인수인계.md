## 1. 데이터 가져오는 두 가지 방법

어느 쪽이든 **바이트 단위로 같은 파일**이 나옵니다. 앱과 스크립트의 출력 동일성은

`_MANIFEST.csv` 의 md5 중복 판별이 그대로 성립합니다.

### A. 스크립트로 직접 (권장)

```sh
# 최초 1회
curl -o archive/00_scripts/fetch_firestore.py \
  https://raw.githubusercontent.com/d2cEng/cas_man/main/tools/fetch_firestore.py
pip install google-cloud-firestore

# 매번
python3 archive/00_scripts/fetch_firestore.py \
  --key <서비스계정 JSON 키 경로> \
  --out archive/09_현금장부/
```

실행하면 CSV 를 쓰고 **md5 와 계좌별 최종 잔액**을 출력합니다 — 4장 검산에 그대로 씁니다.

```
archive/09_현금장부/현금장부_20240102-20240105_12건.csv  (12건)
md5: 0123456789abcdef0123456789abcdef
기록상 최종 잔액:
  현금: 12,345
  와리깡: -6,000
```

옵션: `--uid` (생략하면 자동 탐지), `--tz` (기본 +9 JST — **바꾸지 마세요**, 앱이 폰
현지 시간으로 날짜를 찍습니다).

### B. 폰에서 내보내기

앱 → 설정 → 내보내기 → **거래내역 CSV**. 같이 있는 **인수인계 요약 복사** 를 누르면

## 2. CSV 계약

아래는 형식을 보여주기 위한 **가짜 예시**입니다.

```
날짜,계좌,금액,거래처,범주,출처,비고,잔액
2024-01-02,현금,10000,잔고신고,수입,현금장부,잔고,10000
2024-01-03,현금,20000,ATM,이체,현금장부,"(짝: 은행 -20,000)",30000
2024-01-04,현금,-1200,○○마트,식비,현금장부,,28800
2024-01-05,와리깡,-6000,○○식당,이체,현금장부,丸池,-6000
2024-01-05,현금,6000,○○식당,이체,현금장부,丸池,34800
```

**현금과 와리깡 행만** 들어옵니다 — 이 앱 말고는 기록하는 곳이 없는 돈입니다. 은행·카드
쪽 행은 그쪽 데이터에 있으므로 오지 않습니다.

| 열 | 비고 |
|---|---|
| **A~G** | 「거래내역」 시트와 **완전히 같은 순서**. 이 범위만 복사해 붙이면 됩니다 |
| **G `비고`** | 은행·카드와의 이체면 끝에 `(짝: 계좌 금액)` — 짝 행이 오지 않으므로 어디서 왔는지를 적습니다. 워크북의 현금 쪽 이체 행이 쓰는 형식과 같습니다 |
| **H `잔액`** | **파생값 — 원장에 넣지 마세요.** 계좌별 누계이며, 현금은 지갑과 대조하라고 붙인 것입니다 |

- 정렬은 **날짜 오름차순**, 같은 날짜는 id 순. 내용이 같으면 파일도 같습니다(md5 성립)
- `잔액` 은 행 순서에 의존하므로 시트에서 정렬을 바꾸면 의미가 깨집니다
- 인코딩 UTF-8 + BOM, 줄바꿈 CRLF. `pd.read_csv()` 한 줄로 읽히고 `금액` 은 int64

### 금액 부호

| 구분 | 부호 |
|---|---|
| 지출 | 음수 |
| 수입 | 양수 |
| 이체 | 나가는 행 **음수** · 받는 행 **양수** |

## 3. 반드시 확인할 것

### 은행·카드 쪽 행은 오지 않습니다

ATM 인출이면 현금으로 들어온 행 하나만 옵니다. 은행에서 빠진 쪽은 **행으로 오지 않고**,
비고에 짝으로만 적힙니다.

```
현금  +20000  ATM  이체  현금장부  (짝: 은행 -20,000)
```

은행 쪽 행은 은행 데이터에 있습니다. 거기서 짝을 맞추세요. **ATM 수수료도 은행에서 빠지는
돈이라 오지 않습니다** — 역시 은행 데이터에 있습니다.

### 같은 인출이 두 번 들어가지 않게 — 반드시 확인

워크북은 은행 데이터로 **현금 쪽 유입 행을 이미 만들고 있습니다** (`출처` 가 은행 쪽이고
비고가 `… 현금 유입 (짝: 로킨 -N)` 인 행). 현금장부의 은행발 이체 행은 **같은 인출**입니다.
`출처` 가 다르니 `출처 + 날짜 + 금액` 대조로는 잡히지 않고, 그대로 넣으면 현금이 두 번
들어온 것이 됩니다.

- 비교 대상: 현금장부 행 중 `범주 이체` 이고 짝이 은행·카드 계좌인 것 (`와리깡` 은 다른
  소스가 없어 제외)
- 대조 기준: `계좌 현금 + 금액 + 범주 이체`, 날짜 ±3일, 출처 무관. **날짜는 은행 시스템 시각이
  기준**이라 주말·공휴일 인출은 하루 이틀 밀립니다
- 워크북에 이미 있으면 **현금장부 행은 넣지 않습니다.** 없으면 넣습니다
- 날짜가 정확히 같지 않은 후보는 자동으로 빼지 말고 **목록으로 보고**해 확인받으세요.
  같은 금액을 이틀 연속 뽑는 경우도 있습니다

```python
import pandas as pd
app = pd.read_csv('현금장부_....csv')          # 현금장부 CSV
book = 거래내역_df                              # 워크북 「거래내역」 (출처 무관 전체)
app['날짜'] = pd.to_datetime(app['날짜']); book['날짜'] = pd.to_datetime(book['날짜'])

짝 = app['비고'].fillna('').str.extract(r'\(짝: (\S+) ')[0]     # 은행·카드발 이체만 짝 표기가 있음
cand = app[app['계좌'].eq('현금') & app['범주'].eq('이체') & 짝.notna()]
old = book[book['계좌'].eq('현금') & book['범주'].eq('이체') & book['출처'].ne('현금장부')]
m = cand.reset_index().merge(old, on=['계좌', '금액', '범주'], suffixes=('', '_기존'))
m = m[(m['날짜'] - m['날짜_기존']).abs() <= pd.Timedelta(days=3)]
m['같은날'] = m['날짜'].eq(m['날짜_기존'])
print(m[['index', '날짜', '날짜_기존', '금액', '비고', '비고_기존', '출처_기존', '같은날']])
```

### `와리깡` 은 두 행이 모두 옵니다 — 카드 반영에 쓰세요

와리깡(割り勘)으로 오간 현금은 수입·지출이 아니라 `현금 ↔ 와리깡` 이체입니다. 이 앱 말고는
기록하는 곳이 없으므로 **두 행이 모두 오고**, 서로를 짝으로 삼습니다(`(짝: …)` 표기 없음).

```
와리깡  -6000  KULULU  이체  현금장부  丸池    ← 친구에게 현금으로 받음
현금    +6000  KULULU  이체  현금장부  丸池
```

- **카드로 전액 결제한 건에 반영하세요.** 위 예는 카드로 전액을 내고 남의 몫을 현금으로
  받은 경우입니다. 카드 데이터에는 전액이 지출로 잡혀 있으므로, 그 카드 결제 행에서
  남의 몫(와리깡 −6,000 만큼)을 덜어내야 실제 소비가 됩니다. 같은 날·같은 거래처(비고의
  장소)로 카드 행을 찾으면 됩니다.
- 현금으로 남의 몫까지 낸 경우는 반대 방향입니다(`현금 −` / `와리깡 +`, 지출은 본인 몫만).
  나중에 돌려받으면 `와리깡 −` / `현금 +` 가 들어와 와리깡은 0 으로 닫힙니다.
- `와리깡` 은 실재하는 계좌가 아닙니다. 워크북 「계좌별」 시트에 없으면 추가해야 계좌
  오라클이 성립합니다. 카드 반영까지 끝나면 잔액이 0 이 되는 것이 정상입니다.
- 이체라서 지출·수입 집계에는 영향이 없습니다(규칙 4).

### `잔고신고` 행 중복 주의

앱에서 기초 잔액을 설정하면 이런 행이 하나 들어갑니다.

```
2024-01-02,현금,10000,잔고신고,수입,현금장부,잔고,10000
```

워크북에는 **이미 초기 잔고신고 행들이 있습니다.** 현금 계좌를 이중으로 선언하는
꼴이 되지 않는지 확인하고, 필요하면 이 행만 빼고 넣으세요.

### 삭제 기록은 안 나옵니다

앱은 지운 기록을 클라우드에서 **삭제 시각만 담은 조각**으로 바꿔 두고 90일 뒤 정리합니다.
스크립트가 이 조각을 걸러내므로 CSV 에는 실제 기록만 들어갑니다.

## 4. 반영 절차

1. **중복 확인** (규칙 5) — 두 번 합니다
   - 같은 소스 재반영: `출처 + 날짜 + 금액` 으로 기존 현금장부 행과 대조
   - **같은 인출의 중복**: 은행발 이체 행을 은행 데이터로 만든 현금 유입 행과 대조
     (3장 「같은 인출이 두 번 들어가지 않게」). 겹치는 행은 넣지 않고, 날짜가 다른 후보는 보고
2. **A~G열만** 「거래내역」 시트 끝에 추가
3. **독립 검산** (규칙 5) — 파이썬으로 계좌별 합계를 다시 계산해, 스크립트가 찍은
   `기록상 최종 잔액` 및 시트 수식값과 세 값이 일치하는지 확인
4. **아카이브** (규칙 7) — CSV 를 `archive/` 에 두고 `_MANIFEST.csv` 에 md5 등록
5. **시트 갱신**
   - 「데이터출처」에 `현금장부` 행 추가/갱신 (건수·기간)
   - 「누락데이터」의 현금 지출 기록 항목 갱신
6. **결과 보고** — 현금 잔고 음수가 얼마나 해소됐는지

검산 예시:

```python
import pandas as pd
df = pd.read_csv('현금장부_....csv')
assert list(df.columns[:7]) == ['날짜','계좌','금액','거래처','범주','출처','비고']
assert set(df['계좌']) <= {'현금', '와리깡'}          # 이 앱이 내보내는 계좌만
# 잔액 열이 계좌별 금액 누계와 일치하는지
for a in df['계좌'].unique():
    s = df[df['계좌'] == a]
    assert (s['금액'].cumsum().values == s['잔액'].values).all(), a
# 지출 합계 (이체 제외 — 규칙 4)
지출 = -df.loc[df['범주'].ne('이체') & df['금액'].lt(0), '금액'].sum()
```

## 5. 데이터 모델

앱이 쓰는 값들입니다. 워크북에서 실제로 쓰이는 값만 초기값으로 넣었습니다.

**범주** (지출) — 사용 빈도순
: 식비 · 생활 · 교통 · 빌 · 위생건강 · 전자기기 · 여가 · 주식 · 여행 · 의류 · 아파트 ·
기타 · 엄마 · 가구 · 부엌용품 · 교육 · 선물

수입은 범주 `수입`, 이체는 범주 `이체` 로 고정됩니다 (「범주별」 시트의 구분과 동일).

**계좌**
: 워크북 「계좌별」 시트의 목록을 그대로 씁니다. 앱의 초기값은
`assets/store.js` 의 `DEFAULT_ACCOUNTS` 에 있고, 설정에서 바꿀 수 있습니다.

CSV 의 `계좌` 는 **현금** 또는 **와리깡** 입니다. 은행·카드 계좌 이름은 이체 비고의
`(짝: …)` 에만 나옵니다.
