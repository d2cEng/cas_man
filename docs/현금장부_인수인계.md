## 1. 데이터 가져오는 두 가지 방법

어느 쪽이든 **바이트 단위로 같은 파일**이 나옵니다. 앱과 스크립트의 출력 동일성은
저장소 CI(`tests/csv_parity.py`)가 지킵니다. 그래서 어느 쪽으로 만들었든
`_MANIFEST.csv` 의 md5 중복 판별이 그대로 성립합니다.

### A. 스크립트로 직접 (권장)

```sh
# 최초 1회
curl -o archive/00_scripts/fetch_firestore.py \
  https://raw.githubusercontent.com/d2cEng/cas_man/main/tools/fetch_firestore.py
pip install google-cloud-firestore

# 매번
python3 archive/00_scripts/fetch_firestore.py \
  --key <서비스계정 JSON 키 경로> \
  --out archive/09_현금장부/
```

실행하면 CSV 를 쓰고 **md5 와 계좌별 최종 잔액**을 출력합니다 — 3장 검산에 그대로 씁니다.

```
archive/09_현금장부/현금장부_20240102-20240105_12건.csv  (12건)
md5: 0123456789abcdef0123456789abcdef
기록상 최종 잔액:
  현금: 12,345
  은행: -23,456
```

옵션: `--uid` (생략하면 자동 탐지), `--tz` (기본 +9 JST — **바꾸지 마세요**, 앱이 폰
현지 시간으로 날짜를 찍습니다).

### B. 폰에서 내보내기

앱 → 설정 → 내보내기 → **거래내역 CSV**. 같이 있는 **인수인계 요약 복사** 를 누르면
건수·합계·최종 잔액이 마크다운으로 복사되니, 프롬프트에 붙여 검산 대조값으로 쓰세요.

## 2. CSV 계약

아래는 형식을 보여주기 위한 **가짜 예시**입니다.

```
날짜,계좌,금액,거래처,범주,출처,비고,잔액
2024-01-02,현금,10000,잔고신고,수입,현금장부,잔고,10000
2024-01-03,은행,-20000,ATM,이체,현금장부,,-20000
2024-01-03,현금,20000,ATM,이체,현금장부,,30000
2024-01-03,은행,-110,ATM,기타,현금장부,수수료,-20110
2024-01-04,현금,-1200,○○마트,식비,현금장부,,28800
```

| 열 | 비고 |
|---|---|
| **A~G** | 「거래내역」 시트와 **완전히 같은 순서**. 이 범위만 복사해 붙이면 됩니다 |
| **H `잔액`** | **파생값 — 원장에 넣지 마세요.** 계좌별 누계이며 지갑과 대조하라고 붙인 것입니다 |

- 정렬은 **날짜 오름차순**, 같은 날짜는 id 순. 내용이 같으면 파일도 같습니다(md5 성립)
- `잔액` 은 행 순서에 의존하므로 시트에서 정렬을 바꾸면 의미가 깨집니다
- 인코딩 UTF-8 + BOM, 줄바꿈 CRLF. `pd.read_csv()` 한 줄로 읽히고 `금액` 은 int64

### 금액 부호

| 구분 | 부호 |
|---|---|
| 지출 | 음수 |
| 수입 | 양수 |
| 이체 | 나가는 행 **음수** · 받는 행 **양수** |

## 3. 반드시 확인할 것

### 이체는 두 행입니다

워크북과 같은 방식입니다. 한 번의 인출이 **계좌 두 개에 걸쳐 두 행**으로 들어갑니다.

```
은행    -20000  ATM  이체
현금    +20000  ATM  이체
```

두 행의 합이 0이라 **계좌 오라클(차이 0)이 유지**됩니다. 한쪽만 넣으면 잔고가 깨집니다.

### ATM 수수료는 별도 지출 행

이체는 지출 집계에서 빠지므로(규칙 4), 수수료를 이체 금액에 합치면 실제 소비가
사라집니다. 그래서 **출금 계좌에 `기타` 범주, 비고 `수수료`** 인 지출 행으로 따로 넣습니다.

```
은행  -110  ATM  기타  현금장부  수수료
```

20,000 인출 + 110 수수료 → 계좌 순액 합계 **−110** (이체는 상쇄, 수수료만 차감).

### 은행 데이터와 겹치는 행 — 반드시 걸러낼 것

**`계좌` 가 `현금` 이 아닌 행은 워크북에 이미 있을 수 있습니다.** ATM 인출의 은행 쪽 행과
수수료 행은 은행 거래내역에도 찍히기 때문입니다. `출처` 가 다르니 `출처 + 날짜 + 금액`
대조로는 잡히지 않습니다. 그대로 넣으면 은행에서 두 번 빠진 것이 됩니다.

대조 기준은 **`계좌 + 금액`, 날짜 ±3일, 출처 무관** 입니다. 은행은 주말·공휴일 인출을 다음
영업일에 기장하는 경우가 있어 날짜가 하루 이틀 밀립니다.

| 워크북에 이미 있는 것 | 현금장부에서 넣을 행 |
|---|---|
| 없음 | 이체 두 행 + 수수료 행 전부 |
| 은행 쪽 인출 행만 | **현금 쪽 행만** (은행 행은 기존 것을 짝으로 삼음) |
| 은행 쪽 + 현금 쪽 둘 다 | **넣지 않음** |
| 수수료 행 | 현금장부의 수수료 행을 **넣지 않음** |

- 날짜가 정확히 같지 않은 후보는 자동으로 빼지 말고 **목록으로 보고**해 확인받으세요.
  같은 금액을 이틀 연속 뽑는 경우도 있습니다.
- `와리깡` 행은 다른 소스가 없어 대조 대상이 아닙니다. 현금 쪽 행은 따로 찾지 말고, 위
  표대로 짝인 은행 쪽 행의 결과를 따릅니다.
- 어느 쪽을 넣든 **이체 쌍의 합은 0** 이어야 합니다. 대조 후 계좌 오라클로 확인하세요.

```python
import pandas as pd
app = pd.read_csv('현금장부_....csv')          # 현금장부 CSV
book = 거래내역_df                              # 워크북 「거래내역」 (출처 무관 전체)
app['날짜'] = pd.to_datetime(app['날짜']); book['날짜'] = pd.to_datetime(book['날짜'])

cand = app[app['계좌'].ne('현금') & app['계좌'].ne('와리깡')]
m = cand.reset_index().merge(book[book['출처'].ne('현금장부')], on=['계좌', '금액'], suffixes=('', '_기존'))
m = m[(m['날짜'] - m['날짜_기존']).abs() <= pd.Timedelta(days=3)]
m['같은날'] = m['날짜'].eq(m['날짜_기존'])
print(m[['index', '날짜', '날짜_기존', '계좌', '금액', '거래처', '비고', '출처_기존', '같은날']])
```

### `와리깡` 은 나눠 낸 현금이 오간 자리

이 앱은 **현금흐름만** 기록합니다. 와리깡(割り勘)으로 오간 현금은 수입·지출이 아니라
`와리깡` 과의 이체로 들어옵니다.

```
와리깡  -6000  ○○식당  이체      ← 친구에게 현금으로 받음
현금    +6000  ○○식당  이체
```

- `와리깡` 은 실재하는 계좌가 아니라 **현금의 출처·행선지를 적는 이름**입니다. 워크북
  「계좌별」 시트에 없으면 추가해야 계좌 오라클이 성립합니다.
- 이 앱의 기록만으로 합산한 `와리깡` 잔액에는 의미가 없습니다. 카드로 대신 내고 현금으로
  받은 경우라면 대신 낸 쪽은 카드 데이터에 있습니다. 소비를 정확히 잡으려면 워크북에서 그
  카드 행을 본인 몫 지출과 `카드 → 와리깡` 이체로 나누세요 — 이 앱의 범위 밖입니다.
- 이체라서 지출·수입 집계에는 영향이 없습니다(규칙 4).

### `잔고신고` 행 중복 주의

앱에서 기초 잔액을 설정하면 이런 행이 하나 들어갑니다.

```
2024-01-02,현금,10000,잔고신고,수입,현금장부,잔고,10000
```

워크북에는 **이미 초기 잔고신고 행들이 있습니다.** 현금 계좌를 이중으로 선언하는
꼴이 되지 않는지 확인하고, 필요하면 이 행만 빼고 넣으세요.

### 삭제 기록은 안 나옵니다

앱은 지운 기록을 클라우드에서 **삭제 시각만 담은 조각**으로 바꿔 두고 90일 뒤 정리합니다.
스크립트가 이 조각을 걸러내므로 CSV 에는 실제 기록만 들어갑니다.

## 4. 반영 절차

1. **중복 확인** (규칙 5) — 두 번 합니다
   - 같은 소스 재반영: `출처 + 날짜 + 금액` 으로 기존 현금장부 행과 대조
   - **다른 소스와 겹침**: 현금 외 계좌 행을 `계좌 + 금액 + 날짜 ±3일` 로 은행 데이터와 대조
     (3장 「은행 데이터와 겹치는 행」). 겹치는 행은 넣지 않고, 날짜가 다른 후보는 보고
2. **A~G열만** 「거래내역」 시트 끝에 추가
3. **독립 검산** (규칙 5) — 파이썬으로 계좌별 합계를 다시 계산해, 스크립트가 찍은
   `기록상 최종 잔액` 및 시트 수식값과 세 값이 일치하는지 확인
4. **아카이브** (규칙 7) — CSV 를 `archive/` 에 두고 `_MANIFEST.csv` 에 md5 등록
5. **시트 갱신**
   - 「데이터출처」에 `현금장부` 행 추가/갱신 (건수·기간)
   - 「누락데이터」의 현금 지출 기록 항목 갱신
6. **결과 보고** — 현금 잔고 음수가 얼마나 해소됐는지

검산 예시:

```python
import pandas as pd
df = pd.read_csv('현금장부_....csv')
assert list(df.columns[:7]) == ['날짜','계좌','금액','거래처','범주','출처','비고']
# 잔액 열이 계좌별 금액 누계와 일치하는지
for a in df['계좌'].unique():
    s = df[df['계좌'] == a]
    assert (s['금액'].cumsum().values == s['잔액'].values).all(), a
# 지출 합계 (이체 제외 — 규칙 4)
지출 = -df.loc[df['범주'].ne('이체') & df['금액'].lt(0), '금액'].sum()
```

## 5. 데이터 모델

앱이 쓰는 값들입니다. 워크북에서 실제로 쓰이는 값만 초기값으로 넣었습니다.

**범주** (지출) — 사용 빈도순
: 식비 · 생활 · 교통 · 빌 · 위생건강 · 전자기기 · 여가 · 주식 · 여행 · 의류 · 아파트 ·
기타 · 엄마 · 가구 · 부엌용품 · 교육 · 선물

수입은 범주 `수입`, 이체는 범주 `이체` 로 고정됩니다 (「범주별」 시트의 구분과 동일).

**계좌**
: 워크북 「계좌별」 시트의 목록을 그대로 씁니다. 앱의 초기값은
`assets/store.js` 의 `DEFAULT_ACCOUNTS` 에 있고, 설정에서 바꿀 수 있습니다.

실질적으로는 **현금** 이 대부분이고, 이체 상대 계좌로 은행이 나옵니다.
