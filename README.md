# 현금장부 (cas_man)

카드·계좌와 달리 전자기록이 남지 않는 **현금 결제**를 몇 초 안에 기록하고, 언제든 CSV/JSON으로
꺼낼 수 있는 가계부입니다. 입력 항목과 내보내기 형식은 **`일본 자산 관리` 워크북의 「거래내역」
시트**에 그대로 맞춰져 있습니다.

- **오프라인 우선** — 모든 기록은 먼저 기기(IndexedDB)에 저장됩니다. 지하 주차장이든 비행기든
  입력이 됩니다.
- **구글 계정 동기화** — 일본어 퀴즈 앱(`WEB-JA-Quiz`)과 **같은 Firebase 프로젝트**를 씁니다.
  구글 로그인만 하면 기기 간에 동기화되고, 새로 설정할 것이 없습니다.
- **위젯·단축어 연동** — 홈 화면 아이콘 길게 누르기, iOS 단축어, 안드로이드 위젯에서 URL 하나로
  바로 기록됩니다.
- **어디에나 배포** — 빌드 도구가 필요 없는 정적 파일입니다. GitHub Pages, Netlify, Cloudflare
  Pages, 사내 서버 어디든 그대로 올라갑니다.

> **코워크 세션에 넘길 때는 [`docs/현금장부_인수인계.md`](docs/현금장부_인수인계.md) 를 읽히세요.**
> 데이터 가져오는 법·CSV 계약·반영 절차·주의점이 그 문서 하나에 정리되어 있습니다.

## 자산 관리 워크북과의 관계

한 건의 기록이 「거래내역」 시트의 한 행과 1:1로 대응합니다.

| 앱 입력    | 거래내역 열 | 비고                                                     |
| ---------- | ----------- | -------------------------------------------------------- |
| 거래 일시  | `날짜`      | 시각은 CSV의 H열로 따로 나갑니다                          |
| 계좌       | `계좌`      | 기본값 `현금`. 워크북의 다른 계좌도 선택 가능             |
| 금액 + 구분 | `금액`      | 지출은 음수, 수입은 양수. 이체는 나가는 쪽 음수·받는 쪽 양수 |
| 거래처     | `거래처`    |                                                          |
| 범주       | `범주`      | 구분이 수입이면 `수입`, 이체면 `이체` 로 고정됩니다      |
| —          | `출처`      | 이 앱에서 넣은 행은 `현금장부` 로 표시됩니다             |
| 비고       | `비고`      |                                                          |

- 구분은 워크북의 「범주별」 시트와 같은 **지출 / 수입 / 이체** 세 가지입니다.
- **이체는 두 행으로 기록됩니다** — 나가는 계좌 음수, 들어오는 계좌 양수. 워크북이 쓰는 방식
  그대로라 계좌 잔고가 맞아떨어집니다(계좌 오라클 차이 0). 목록에서는 한 줄로 보이고, 어느
  쪽을 눌러도 쌍으로 편집되며, 지우면 양쪽이 함께 지워집니다.
- **이체 기본값은 `은행 → 현금`** (은행에서 현금 뽑기)입니다. 지출·수입의 기본 계좌는
  `현금` 이고, 둘 다 설정 → 계좌 관리에서 바꿀 수 있습니다. 방향은 **⇅ 버튼 한 번**으로
  뒤집힙니다.
- 내역 화면에 **계좌별 현재 잔액**이 표시됩니다(현금 우선). 이 앱에 입력한 기록만의 합계라,
  기초 잔액이 없는 은행·카드 계좌는 실제 잔고와 다릅니다 — 화면에도 그렇게 적혀 있습니다.
- **ATM 수수료**는 이체가 아니라 **별도 지출 행**이지만, 그 이체와 한 묶음으로 저장됩니다.
  어느 행을 눌러 고치든 날짜·거래처·비고가 세 행에 함께 반영되고, 지우면 함께 지워집니다. 이체는 지출 집계에서 빠지므로,
  수수료를 이체에 합치면 실제 소비가 잡히지 않습니다. 출금 계좌에 `기타` 범주, 비고 `수수료`
  로 기록됩니다.
- 범주와 계좌 목록의 초기값은 워크북에서 실제로 쓰이는 값들이고, 범주는 사용 빈도가 높은
  순서(식비·생활·교통…)로 정렬되어 있습니다. **설정** 에서 자유롭게 추가·삭제할 수 있습니다.
- 월별 요약의 `지출` 은 **이체를 제외**한 금액입니다. 계좌 간 이동은 지출이 아니기 때문입니다.

## 배포

`main` 브랜치에 푸시하면 `.github/workflows/pages.yml` 이 GitHub Pages로 배포합니다.

**처음 한 번은 저장소 설정이 필요합니다.** 저장소 **Settings → Pages → Source** 를
*GitHub Actions* 로 바꿔주세요. 워크플로의 `GITHUB_TOKEN` 으로는 Pages 사이트를 새로 만들 수
없어서(`Resource not accessible by integration`), 이 단계 전까지는 배포가 실패합니다. 한 번
켜두면 이후 푸시부터는 자동으로 배포됩니다.

다른 호스팅을 쓴다면 저장소 전체를 정적 파일로 업로드하기만 하면 됩니다. 경로가 모두 상대
경로라 `https://example.com/` 든 `https://example.com/ledger/` 든 그대로 동작합니다.

> 서비스 워커와 구글 로그인은 **HTTPS**(또는 `localhost`)에서만 동작합니다.

## 안드로이드에 설치

크롬으로 배포 주소를 열고 **설정 → 홈 화면에 설치 → 앱 설치** 를 누르면 됩니다. 브라우저
메뉴(⋮)의 *앱 설치* 로도 같습니다.

설치하면 주소창 없이 앱처럼 열리고, 아이콘을 길게 누르면 *지출 빠른입력 / 수입 빠른입력 /
이번 달 내역* 바로가기가 나옵니다. 오프라인에서도 입력·조회가 되고, 다시 온라인이 되면
자동으로 동기화됩니다.

아이폰은 Safari에서 **공유 → 홈 화면에 추가** 입니다(iOS는 앱 내 설치 버튼을 지원하지 않습니다).

## 클라우드 동기화

설정 → 클라우드 동기화에서 **구글 로그인** 만 누르면 됩니다.

전용 Firebase 프로젝트 `cas-man-ca57a` 를 씁니다. 일본어 퀴즈 앱과 계정은 같지만 프로젝트는
분리되어 있어, 한쪽의 OAuth 검증 상태나 보안 규칙이 다른 쪽에 영향을 주지 않습니다.

기록은 본인 계정 아래에만 저장됩니다.

```
users/{uid}/cashman/{recordId}
```

`apiKey` 가 저장소에 그대로 있는 것은 정상입니다. 접근 제어는 키가 아니라 **Firestore 보안
규칙**이 합니다.

### 프로젝트 설정 (최초 1회)

새 프로젝트에 이 앱을 붙일 때 필요한 전부입니다.

| 콘솔 위치 | 할 일 |
|---|---|
| 프로젝트 설정 → 내 앱 → `</>` | 웹 앱 등록 → 나온 `firebaseConfig` 를 `assets/sync.js` 에 반영 |
| Authentication → 시작하기 | 로그인 제공업체 **Google** 사용 설정 |
| Authentication → 설정 → 승인된 도메인 | `d2ceng.github.io` 추가 (없으면 `auth/unauthorized-domain`) |
| Firestore Database → 만들기 | 위치 `asia-northeast1`(도쿄), 프로덕션 모드 |
| Firestore → 규칙 | 아래 규칙 게시 |

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{uid}/cashman/{recordId} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }
  }
}
```

규칙이 빠지면 앱이 설정 화면에 **붙여넣을 규칙과 콘솔 링크를 그대로 띄워줍니다.**

### 충돌 처리

기록마다 `updatedAt` 을 들고 다닙니다. 동기화는 원격을 읽어 **기록 단위로 최신 것을
남기고**(last write wins) 바뀐 것만 올립니다. 서버가 중재하지 않아도 여러 기기가 같은 상태로
수렴합니다. IndexedDB가 원본이고 Firestore는 전송 수단이라, 오프라인에서도 입력은 그대로 됩니다.

**삭제는 즉시, 완전히** 이뤄집니다. 기기에서 바로 지우고, 다음 동기화 때 클라우드 문서도
지웁니다. 표식을 남겨두지 않습니다. 대신 아직 클라우드에서 못 지운 id만 잠깐 대기열에 들고
있다가(오프라인에서 지운 경우), 클라우드 사본이 사라지면 그 id도 버립니다. 이 대기열이 없으면
동기화가 "내게 없는 새 기록"으로 보고 도로 받아옵니다.

### 삭제 로그

지운 기록은 바로 사라지지만, 클라우드의 그 문서는 **삭제 시각만 담은 조각**으로 바뀝니다
(`{ tombstone: true, deletedAt }`). 기록 본문이 아니라 약 50바이트짜리이고(기록 한 건은
~200바이트), **90일이 지나면 양쪽에서 자동 정리**됩니다. 같은 컬렉션 안에 두므로 이것 때문에
보안 규칙을 손댈 일은 없습니다.

이 로그가 있어야 `삭제` 와 `수정` 이 부딪혔을 때 판단할 수 있습니다.

| 상황 | 결과 |
|---|---|
| 삭제 시각 < 수정 시각 | 수정이 나중이므로 **되살립니다** (로그 항목도 폐기) |
| 삭제 시각 > 수정 시각 | 삭제가 나중이므로 **지웁니다** |

로그가 만료됐거나 애초에 없던 경우를 위한 보루로 **마지막 동기화 시각**도 함께 봅니다. 클라우드에
없는 로컬 기록의 `updatedAt` 이 마지막 동기화보다 이전이면 그때 클라우드에 있었다는 뜻이므로 다른
기기가 지운 것이고, 이후면 아직 못 올린 새 기록입니다. 이 둘은 **같은 기기의 시계**라 시계 오차를
타지 않고, 첫 동기화(마지막 동기화 = 0)에서는 아무것도 지우지 않습니다.

> 이 규칙 때문에, 클라우드가 통째로 비면 이 기기의 기록도 지워집니다. 한 기기에서 "모든 기록
> 삭제" 를 하면 다른 기기에도 전파되는 것이 의도된 동작입니다. 중요한 시점에는 **JSON 백업**을
> 받아두세요.

## 위젯 · 단축어로 한 번에 기록하기

**설정 → 위젯 · 단축어 연동** 에서 주소를 만들어 복사하세요. 형태는 이렇습니다.

```
https://내주소/?add=1&type=expense&amount=480&category=교통&account=현금&save=1
```

| 파라미터   | 설명                                            |
| ---------- | ----------------------------------------------- |
| `add=1`    | 입력 화면으로 진입                              |
| `type`     | `expense`(기본) · `income` · `transfer`         |
| `amount`   | 금액                                            |
| `category` | 범주 이름. 등록된 범주와 이름이 같아야 선택됨   |
| `account`  | 계좌 이름. 생략하면 기본 계좌(`현금`)           |
| `payee`    | 거래처                                          |
| `memo`     | 메모                                            |
| `save=1`   | 열자마자 즉시 저장 (금액이 있을 때만)           |
| `view`     | `history` 로 주면 내역 화면으로 바로 이동       |

저장 후에는 주소에서 파라미터를 지우므로, 새로고침해도 같은 결제가 두 번 기록되지 않습니다.

- **iOS** — 단축어 앱 → 새 단축어 → *URL 열기* 에 위 주소를 넣고 홈 화면에 추가합니다.
  버스비처럼 금액이 고정된 지출은 `save=1` 로 두면 한 번 탭에 기록이 끝납니다.
- **안드로이드** — 앱을 홈 화면에 설치(PWA)하면 아이콘을 길게 눌러 *지출 빠른입력 / 수입
  빠른입력 / 이번 달 내역* 바로가기를 쓸 수 있습니다. 임의 금액 위젯은 바로가기 생성 앱에서 위
  주소를 등록하세요.
- **공유하기** — 다른 앱에서 금액이 담긴 텍스트를 공유하면 숫자를 뽑아 금액으로 채웁니다.

## 내보내기 — 종합가계부로 넘기기

이 앱은 종합가계부의 남은 작업 중 **「현금 지출 기록 — 수기 입력 필요」**
를 메우는 소스입니다. 그래서 내보내기가 `archive/` → `build_ledger.py` 흐름에 그대로 얹히도록
맞춰져 있습니다.

### 1. 거래내역 CSV — 원본 소스 파일

```
현금장부_20240102-20240105_12건.csv
```

- A~G열은 「거래내역」 시트와 **완전히 동일**: `날짜, 계좌, 금액, 거래처, 범주, 출처, 비고`.
  그 범위만 복사하면 시트에 그대로 붙습니다. `pd.read_csv()` 한 줄로 읽힙니다.
- **H열 `잔액`** — 그 행까지의 **계좌별 누계**입니다. 지갑에 실제로 있는 현금과 바로 대조하라고
  넣었습니다. 파생값이라 시트에서 **정렬을 바꾸면 의미가 깨지니** 대조용으로만 쓰세요. 기초
  잔액이 없는 은행·카드 계좌는 실제 잔고와 다르고, 현금만 지갑과 1:1로 맞습니다.
- **날짜 오름차순**, 같은 날짜는 id 순 — 내용이 같으면 파일도 같으므로 **md5 중복 판별**이
  성립합니다 (규칙 7).
- 금액은 **지출 음수 / 수입 양수**, 이체는 **나가는 행 음수 · 받는 행 양수** 로 쌍을 이룹니다.
- `출처` 는 전부 `현금장부` — 새 소스에 새 출처명을 주는 규칙 6에 맞춥니다.
- 파일명에 기간·건수가 들어가 `archive/` 에 그냥 쌓아도 충돌하지 않고, 어느 구간을 담았는지
  파일명만 봐도 압니다.

### 2. 인수인계 요약 — 검산용

규칙 5(추가 후 파이썬 독립 검산)의 **대조값**입니다. 버튼 하나로 마크다운이 복사되고, 코워크
세션 프롬프트에 그대로 붙여넣으면 됩니다.

아래 수치는 형식을 보여주기 위한 **가짜 예시**입니다.

```markdown
## 현금장부 내보내기

- 파일: `현금장부_20240102-20240105_12건.csv`
- 기간: 2024-01-02 ~ 2024-01-05
- 건수: 12건 (지출 9 / 수입 1 / 이체 2)
- 지출 합계: 12,345
- 수입 합계: 10,000
- 이체 합계: 20,000 (수입·지출 집계 제외)
- 계좌: 현금, 은행
- 출처: 현금장부

### 기록상 최종 잔액

- 현금: 12,345
- 은행: -23,456
```

### 3. JSON 백업 — 기기 이전용

id까지 담은 무손실 백업입니다. 가계부로 넘길 때 쓰는 파일이 아니라, 폰을 바꾸거나
브라우저 데이터를 지우기 전에 받아두는 용도입니다.

### 코워크가 직접 읽기

폰에서 내보내는 대신, 코워크 세션이 Firestore 에서 바로 같은 CSV 를 만들 수 있습니다.

```sh
pip install google-cloud-firestore
python3 tools/fetch_firestore.py --key ~/keys/cas-man-reader.json --out archive/
```

**서비스 계정 만들기 (최초 1회)**

1. [GCP 콘솔 → IAM 및 관리자 → 서비스 계정](https://console.cloud.google.com/iam-admin/serviceaccounts?project=cas-man-ca57a)
   에서 계정을 만듭니다 (예: `cas-man-reader`).
2. 역할은 **`Cloud Datastore 뷰어`(roles/datastore.viewer)** 만 줍니다 — 읽기 전용입니다.
3. 키 → 새 키 만들기 → **JSON** 을 받아 맥에 둡니다.

> 키는 자격증명입니다. **git 에도 `archive/` 에도 넣지 마세요.** 잃어버리면 콘솔에서 그 키만
> 폐기하면 됩니다.

출력은 앱의 내보내기와 **바이트 단위로 같습니다** — 열·정렬·잔액·파일명·BOM까지. 그래서 어느
쪽으로 만들었든 `_MANIFEST.csv` 의 md5 중복 판별이 그대로 성립합니다. 이 동일성은
`tests/csv_parity.py` 가 CI에서 지킵니다.

실행하면 md5와 계좌별 최종 잔액을 함께 찍어주므로 규칙 5 검산에 바로 씁니다.

### 가져오기

CSV와 JSON 둘 다 받습니다. **CSV에 id 열이 없어도 중복이 생기지 않습니다** — 행 내용
(날짜·계좌·금액·거래처·범주·비고)에서 안정적인 id를 만들기 때문에, 같은 파일을 두 번 넣어도
같은 행을 덮어쓸 뿐입니다. 시트에서 A~G열만 복사해 CSV로 저장한 뒤 넣어도 됩니다.

## 현금 기초 잔액

**설정 → 현금 기초 잔액** 에 이 앱을 쓰기 시작한 시점의 지갑 현금을 넣어두면, 내역의 현금
잔액과 CSV의 `잔액` 열이 **실제 지갑과 바로 맞습니다.**

워크북이 이미 쓰는 방식 그대로 기록 한 건으로 남습니다.

```
2024-01-02,현금,10000,잔고신고,수입,현금장부,잔고,10000
```

- 날짜 기본값은 **첫 기록 하루 전** 이라 누계의 시작점이 됩니다.
- 다시 저장하면 같은 행을 고칩니다 — 눌러도 쌓이지 않습니다.
- 삭제하면 0에서 시작하는 상태로 돌아갑니다.

## 표시 통화

**설정 → 표시 통화** 에서 円(기본) · 원 · $ 중에 고를 수 있습니다. 금액은 정수로만 저장되므로
통화를 바꿔도 기록은 변하지 않으며, 키패드의 0 묶음 키가 통화에 맞춰 `00`/`000` 으로 바뀝니다.
